# Eyetracking

Gaze recordings (EyeLink `.edf`, or pre-processed `.tsv` / `.tsv.gz` tables) with a JSON
sidecar. Eyetracking is a **BIDS passthrough** modality: PRISM applies BIDS naming
and checks the sidecar against the schema below, but does not rewrite the data itself.

## File name structure

`sub-<label>[_ses-<label>]_task-<label>[_trackedEye-<left|right|both>]_<eyetrack|eye|gaze>.<tsv|tsv.gz|json|edf|asc>`

| Entity | Description |
| --- | --- |
| `sub` | **Required**. The subject identifier. |
| `ses` | Optional. The session identifier. |
| `task` | **Required**. The task during which gaze was recorded. |
| `trackedEye` | Optional. `left`, `right` or `both`. |
| suffix | **Required**. `eyetrack` (what the converter writes), `eye` or `gaze`. |

Files live in `eyetracking/` under the subject (or session). The grammar is defined in
[`entities.schema.json`](../../app/schemas/stable/entities.schema.json); see
[Entities and filename grammar](entities.md).

## Sidecar JSON

The sidecar requires `Manufacturer`, `SamplingFrequency`, `RecordedEye`,
`ScreenResolution`, `ScreenDistance`, `TaskName`, `SchemaVersion` and `CreationDate`.
The Studio converter writes a minimal sidecar (sampling frequency and duration are read
from the EDF header when possible); complete the rest in the
[JSON Editor](../studio/json_editor.md). Missing or mistyped fields are reported as
`PRISM301` / `PRISM302` (see [Error codes](../ERROR_CODES.md)).
