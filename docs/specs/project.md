# Project metadata (`project.json`)

`project.json` sits at the project root and describes the *study*, not a data file:
who is studied, how, in which sessions and with which tasks. Studio writes it from the
[Projects](../studio/projects.md) page. It is validated against `project.schema.json`
and drives the methods text, the eligibility checks and the procedure checks.

## What it controls

| Block | Used for |
| --- | --- |
| `Metadata`, `StudyDesign`, `Recruitment`, `DataCollection` | Study metadata; the Methods Readiness score and the generated Methods section |
| `Eligibility` | Inclusion / exclusion criteria. Each criterion can be linked to a `participants.tsv` column; the validator then warns per participant outside the limits (`PRISM602`, `PRISM603`) |
| `Sessions`, `TaskDefinitions` | The declared procedure. The validator compares it with what is on disk (`PRISM701`-`PRISM706`) |
| `Conditions`, `Procedure` | Experimental groups and extra procedural detail |
| `Preregistration` | Optional data status, hypotheses, outcomes and analysis plan for the AsPredicted-style draft |
| `SchemaVersions`, `SchemaVersionsAcknowledged` | The schema version each modality is validated against in this project (see [Schema versioning](../SCHEMA_VERSIONING.md)) |

Session labels are free-form strings: `pre`, `1` and `01` are three different sessions.
PRISM never normalizes them.
