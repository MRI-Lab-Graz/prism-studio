# Physio

Physiological recordings such as ECG, EDA, respiration, PPG and EMG, with a JSON sidecar describing the recording.

## File name structure

Two layouts, depending on whether the recording belongs to a task:

| Layout | Where | Name |
| --- | --- | --- |
| **Task-free** (PRISM `physio` modality) | `sub-<label>/[ses-<label>/]physio/` | `sub-<label>[_ses-<label>][_acq-<label>][_run-<n>][_recording-<label>]_physio.<tsv.gz\|tsv\|json\|edf>` |
| **Task-bound** (standard BIDS) | `beh/`, `func/` or `eeg/` | `sub-<label>[_ses-<label>]_task-<label>[_recording-<label>]_physio.tsv.gz` + `.json` |

A `task-` entity inside `physio/` is an error. Raw EDF files are not task-bound BIDS
data and are never placed in `beh/`, `func/` or `eeg/`. The old `physiological/` folder
and the `events/` folder no longer exist; the validator reports both with a fix hint.

| Entity | Description |
| --- | --- |
| `sub` | **Required**. The subject identifier. |
| `ses` | Optional. The session identifier. |
| `task` | Only for task-bound physio in `beh/`, `func/`, `eeg/`; not allowed in `physio/`. |
| `acq`, `run` | Optional. |
| `recording` | Optional. The signal type: `ecg`, `cardiac`, `puls`, `resp`, `eda`, `ppg`, `emg`, `temp`, `bp`, `spo2`, `trigger`, or any other alphanumeric label. |
| `physio` | **Required**. The suffix indicating the modality. |

In Studio, the [Physio converter](https://prism-studio.readthedocs.io/en/latest/studio/converter_physio.html) writes either layout
(`--destination` on the CLI) and the File Management renamer follows the same rule.

## Sidecar JSON (`*_physio.json`)

The sidecar requires the `Technical` and `Metadata` blocks. `Study.TaskName` is required
only when a `Study` block is present; `Recording`, `Channels`, `TriggerAnnotations`,
`Acquisition` and `Processing` are optional. The authoritative definition is
[`physio.schema.json`](../../app/schemas/stable/physio.schema.json), listed below.
