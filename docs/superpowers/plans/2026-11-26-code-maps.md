# Project Code Maps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Survey imports find participant code maps in `code/` by name, with task and session scopes, and no export or share contains them.

**Architecture:** One new module `src/code_maps.py` reads and resolves maps. The survey converter calls it where it already applies `--id-map`, moved later so that session labels are known. Every copy-out path asks one predicate whether a file is a code map. Studio gets no new logic.

**Tech Stack:** Python standard library (`csv`, `pathlib`), pandas as already used in the converter, pytest.

**Spec:** [docs/superpowers/specs/2026-11-26-code-maps-design.md](../specs/2026-11-26-code-maps-design.md)

**Branch:** worktree from `origin/main` (local `main` was 3 commits behind on 2026-11-26). Copy the spec and this plan into it.

## Global Constraints

- THE CLI EXECUTES, STUDIO ONLY TRIGGERS: no logic in `app/src/web/**` or JavaScript.
- Files: `code/<modality>_code_map.tsv`, `<modality>_task-<label>_code_map.tsv`, `<modality>_ses-<label>_code_map.tsv`, `<modality>_task-<label>_ses-<label>_code_map.tsv`. Order `task`, then `ses`.
- Header: `code<TAB>participant_id`. Codes match ignoring case and surrounding spaces.
- Session labels are exact strings (no number normalization), as written to the dataset.
- Precedence: task+ses, then task or ses (disagreement stops), then general.
- The tasks of one row resolving to different participants stops the import; nothing is written.
- Code maps are never exported or shared, whatever the include options say, and are kept out of git.
- Mirror check before editing `app/src/` business logic: `python3 -c "import src.converters.survey as m; print(m.__file__)"`.
- Examples and test data use invented codes only, never real ones.

## Review Focus

Each line has its test in the named task.

1. Columns in reverse order (`participant_id, code`): read by header name, never by position; a missing header stops. (Task 2)
2. Excel-saved file (BOM, CRLF), or a row with an empty `participant_id`: reads correctly; the empty row counts as not listed. (Task 2)
3. `survey_code_map.csv` or `Survey_Code_Map.tsv`: stops with the expected name instead of being ignored. (Task 2)
4. `004` in one file and `sub-004` in another: same participant, no false conflict. (Task 2)
5. Copies and backups (`code/old/survey_code_map.tsv`, `code/survey_code_map - Kopie.xlsx`): also left out of export and git. (Task 1)

## Not in this plan

- Code maps for the other importers (biometrics, environment, biosample, participants, batch). Task 3 lists them as known gaps; they need a second plan. The feature is not complete until that list is empty.
- `survey import-limesurvey batch` is refused inside projects, so it never sees project maps and is unchanged. (The spec's note about it needs no code.)

### Task 2: Read and resolve code maps

**Files:**

- Test: `tests/test_code_maps.py`

**Interfaces:**
- Produces:

```python
class CodeMapError(ValueError): ...

@dataclass(frozen=True)
class CodeMap:
    name: str                  # file name
    task: str | None
    session: str | None        # without "ses-"
    entries: dict[str, str]    # code.strip().casefold() -> "sub-<label>"

def load_code_maps(project_root: str | Path, modality: str) -> list[CodeMap]
def resolve_row(maps: list[CodeMap], code: str, tasks: Iterable[str],
                session: str | None) -> tuple[str, tuple[str, ...]] | None
    # (participant_id, names of the files used); None = some task has no entry
```

`session` may be given as `"3"` or `"ses-3"`. With no tasks, resolve as if `task` were None.

- [ ] **Step 1: Write the failing tests** (`write(project, name, *rows)` helper writes `code/<name>` with the header)

```python
def test_narrow_file_wins_and_the_rest_falls_back(project):
    write(project, "survey_code_map.tsv", ("AAAA", "sub-001"), ("BBBB", "sub-002"))
    write(project, "survey_task-ads_code_map.tsv", ("AAAA", "sub-009"))
    maps = load_code_maps(project, "survey")
    assert resolve_row(maps, "aaaa ", ["ads"], None)[0] == "sub-009"
    assert resolve_row(maps, "BBBB", ["ads"], None)[0] == "sub-002"
    assert resolve_row(maps, "AAAA", ["pss"], None)[0] == "sub-001"
    assert resolve_row(maps, "ZZZZ", ["ads"], None) is None

def test_tasks_of_one_row_must_agree(project):   # same two files
    with pytest.raises(CodeMapError, match="ads.*sub-009|sub-009.*ads"):
        resolve_row(maps, "AAAA", ["ads", "pss"], None)
```

Further tests, each asserting the named result:
- `task+ses` beats `task` and `ses`.
- `task-ads` and `ses-3` disagree: `CodeMapError` naming both files; agree: resolves.
- `ses-1` file does not apply to session `01`.
- Session None while an applicable `ses-` file lists the code: `CodeMapError` containing `--session`. Session None and the code not in any `ses-` file: resolves.
- Same code twice with different participants in one file: `CodeMapError`; twice with the same participant: fine.
- `survey_taks-ads_code_map.tsv`, `survey_ses-3_task-ads_code_map.tsv`, `survey_run-1_code_map.tsv`: `CodeMapError` naming the file.
- `biometrics_code_map.tsv` is not loaded for `survey`.
- Review Focus 1 to 4: reversed columns read by name; missing `code` or `participant_id` header stops; BOM and CRLF; empty `participant_id` row ignored; `survey_code_map.csv` and `Survey_Code_Map.tsv` stop with `expected survey_code_map.tsv`; `004` and `sub-004` are one participant.

- [ ] **Step 2: Run** `pytest tests/test_code_maps.py -q`, expect FAIL.

- [ ] **Step 3: Implement.** `csv.DictReader`, `encoding="utf-8-sig"`, tab delimiter. Only files directly in `code/`; a candidate is any whose lower-cased name starts with `<modality>_` and contains `code_map` (a copy such as `survey_code_map - Kopie.tsv` therefore stops the import too, rather than being silently ignored). Parse with `re.fullmatch(rf"{modality}(?:_task-([A-Za-z0-9]+))?(?:_ses-([A-Za-z0-9]+))?_code_map\.tsv", name)`. Normalize `participant_id` by prefixing `sub-` when absent. Project files are untrusted: unreadable or undecodable files raise `CodeMapError`, never a traceback.
